# Mobile View

本次改造在当前 React 19 / Vinext 文件路由应用中完成，没有新增独立应用、第三方依赖、后端接口或工作簿数据格式。现有桌面表格继续保留。

## 架构与阶段

1. **共享逻辑确认**：`app/page.tsx` 的 Home 持有唯一 Scheduler、工作簿状态、连接参数和 SpeechPlayer；通过 `useSyncExternalStore` 订阅更新。Scheduler 按行 ID 与列 ID 绑定任务，提供依赖规划、并发、超时、重试、取消、修订检查与流式预览。它只在 Home 卸载时停止，切换子视图或关闭详情不会卸载 Home。
2. **手机总览**：`components/mobile-sheet.tsx` 保留行列顺序，表格主体双向滚动，列宽 210–300px，预览最多四行且 DOM 文本截取至 600 字符。完整结果留在原状态中，复制时使用全文。手机端没有单元格滚动或尺寸拖动；桌面尺寸设置保持原值。
3. **统一详情**：`components/row-detail-sheet.tsx` 同时处理已有行和新增草稿，各列纵向展示。详情内容只有一个纵向滚动区域。点击列会定位并突出该卡片；长文本完整显示，编辑框随内容增高。已有行调用原 `engine.edit` 自动保存并标记下游需要更新。
4. **快捷录入与运行**：新增草稿在提交时原子创建真实记录，返回唯一 ID，再执行原 Scheduler。三种提交动作分别保留真实行详情、切换空白草稿、关闭详情；后台任务仍绑定原真实记录。同步提交锁和短暂按钮禁用防止重复创建，连续录入保留上次输入列。
5. **体验**：表格顶部／底部按钮定位真实滚动容器；打开详情锁定背景，关闭后原表格位置保持，视图切换也恢复手机表格位置。`visualViewport`、`100dvh` 和 safe-area 处理键盘及安全区域。详情具有焦点约束、关闭按钮和未提交草稿保存确认。
6. **验证**：核心与浏览器测试覆盖以下行为；生产构建与类型检查另外执行。测试不会调用用户密钥或付费模型。

## 使用

小于 768px 的视口默认手机版，其他宽度默认电脑版。菜单可手动覆盖，保存在 `chainflow-view-preference-v1`；选择自动适配会恢复宽度判断。手机浏览器请求桌面网站未必改变视口，此时直接使用应用菜单。平板、旋转及手动电脑版仍可横向查看宽表格。

手机默认收起较复杂的工具；在菜单打开「工作簿与运行设置」即可管理工作表、导入导出、载入示例、模式与执行参数。已有列设置、导入拆句和执行记录继续使用原组件。

点击格子打开整行详情；右下角 + 打开同一个组件的空白状态。A 列可以留空并在 B、C 等列输入。已有行编辑即时保存，新草稿关闭时可保存而不运行、继续编辑或丢弃。

三种动作：

- **运行**：保存并提交后仍留在该真实行，直接查看状态、流式内容和结果。
- **运行并新增**：立即在后台执行当前行，详情切到下一条空白草稿，无需等待模型。
- **运行并关闭**：提交后回到表格，任务继续运行。

所有内容保存后，即使未连接 API 或模型仍保留记录；补好连接可再运行。失败、取消、排队等状态由原引擎提供。停止按钮沿用停止全部任务的语义，不另建手机队列。

## 任意起点与依赖语义

整行提交将有内容且状态完成的格子视为可用来源，沿实际 DAG 计算尚未完成的下游。多输入节点必须所有来源可用；没有来源的分支跳过并提示。A→B→C→D 中仅填 B 时只执行 C、D，A 保持空白，B 不会被重新生成。

若同时手动填写 A、C，同批运行 B 时不能使 C 及基于 C 的 D 被错误标记失效。因此 Scheduler 增加仅对此次运行有效的完成来源边界。原桌面运行入口没有传入该选项，行为保持不变；之后手动编辑上游仍按原规则使下游需要更新。单独点击节点运行仍遵守原节点的依赖规划与重跑语义。

任务输出始终写入真实 ID，不使用详情中的临时值；行排序、关闭详情、连续新增不会改变输出目标。既有修订校验防止迟到请求覆盖新编辑。

## 测试与实际限制

已通过 150 项核心／服务端测试，以及 26 项 UI 测试（4 项桌面 Chromium，11 项手机 Chromium，11 项手机 WebKit）。覆盖四行预览与长文本全文复制、点 C 定位、B 起点、三次连续录入、运行并关闭、历史与编辑失效规则、未保存草稿、100 行导航和滚动恢复、跨视图执行、重复提交、API 错误、网络错误、停止与迟到结果、流式输出和 TTS 接口复用。界面截图经过检查。

浏览器测试采用明确标识的模拟 API 和音频对象，验证真实客户端及调度器；不等于此次已验证真实付费生成或手机音频播放。生产模型／TTS 调用层没有重新实现。

运行检查：

```sh
npm run typecheck
npm test
PLAYWRIGHT_BROWSERS_PATH=.cache/ms-playwright npm run test:ui
npm run build
```

UI 测试需要先启动 `npm run dev`（默认 3002）并安装对应 Playwright Chromium、WebKit 浏览器；可通过 `PLAYWRIGHT_BASE_URL` 改变测试地址。测试在独立浏览器上下文运行，不修改现有浏览器工作簿。

待人工验证：真实 iPhone Safari 与 Android Chrome 的软键盘、输入法、屏幕旋转、安全区域、长按选择与剪贴板许可，真实 TTS 自动播放限制，以及系统切到后台／锁屏后的网络暂停行为。浏览器仿真不能保证这些硬件及操作系统行为。

当前工作表上限仍是 500 行，没有新增虚拟列表。总览不渲染完整长文本，详情只渲染当前行；低端设备在较多列、500 行或频繁流式更新时仍可能需要进一步性能优化。关闭详情或切换视图不取消任务；刷新或关闭整个页面仍遵守既有中断与状态恢复规则。

## 数据、跨设备与后续部署

工作簿仍由 `core/workspace.ts` 保存于当前浏览器 localStorage `chainflow-workspace-v1`；行、列、配置、历史及尺寸共享，没有手机独立数据源，也没有 IndexedDB 或服务端工作簿同步。连接凭证不放进工作簿或导出内容，记住密钥仍由既有可选连接设置处理。

同一浏览器切换视图立即使用同一份内存数据与执行状态。不同手机／电脑，甚至 localhost、127.0.0.1 与局域网 IP 不同来源，数据各自独立。访问相同 Docker 服务仅共享服务端请求入口，不能自动共享表格。可先用 JSON 手动迁移；真正同步还需服务端工作簿持久化、身份与访问控制、冲突处理及运行状态协同。

此次没有部署 PWA、Tunnel、新 Docker 镜像或 DMG。后续 PWA 需 manifest、图标、HTTPS 与明确的离线／更新策略；远程访问需 HTTPS、访问控制和适合公开环境的接口安全审查。不要把现有本地 Codex 订阅接口未经隔离开放到公网。
